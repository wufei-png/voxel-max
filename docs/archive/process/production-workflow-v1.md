# 方块表情包生产流程 v1（归档）

> 历史文档，仅保留早期阶段设计和决策来源。已完成首包以 [`../../../projects/fangxin/packs/shangbanzhong/README.md`](../../../projects/fangxin/packs/shangbanzhong/README.md) 为准；本文件中的阶段状态、路径和“已通过”表述均可能过时。

## 1. 目标

当前阶段只做一件事：

> 用最低成本完成 8 个统一角色、语义清楚、可导出的动态表情。

在这件事没有通过前，不扩 24 张，不做长动画，不做过度工程化量产。

## 2. 当前推荐路线

当前推荐采用：

> GPT 生图 + 修图微调 + 多帧拼 GIF。

判断原因：

- 目标是完成可发布的动态首发包，同时验证可复用的制作流程。
- 方块角色结构简单，适合用少量关键帧、确定性图层和短循环控制成本。
- 早期更需要筛风格和识别度，而不是先做 PSD / AE 工程。
- 微信、飞书、小红书可以共用一套创意资产，只在导出规格上分开。

## 3. 执行前提

开始出图前先锁定下面三份约束：

1. 角色与视觉规则：见 [方芯身份规范](../../../projects/fangxin/identity/spec.md)
2. 出图提示模板：见 [首包生成指南](../../../projects/fangxin/packs/shangbanzhong/generation-guide.md)
3. 逐帧动作定义：见 [首包动作卡](../../../projects/fangxin/packs/shangbanzhong/motion-spec.md)
4. 当前交付范围：首发 8 个表情全部做动态版本

如果需要恢复该流程中的做法，先与当前角色规范核对，不回退到旧 brainstorming 版本。

## 4. 阶段一：母版与先行关键帧验证

### 4.1 产出目标

- 1 张正式 v6 母版
- 8 份已收敛动作卡
- S01、S08 两组先行关键帧
- S01、S08 的浅色与深色背景验证图

### 4.2 A 关卡：母版验证

1. 正式母版固定为 `assets/motherboard-test/motherbase-b-notch-b1-v6.png`。
2. v6 只定义角色身份，不承载 S01-S08 的状态动作。
3. 生图阶段统一禁止模型直接生成文字、对白框或标题。
4. v6 当前白底 RGB 图只作为身份参考；动作关键帧使用纯洋红 `#FF00FF` 工作背景，不要求模型直接输出 Alpha。
5. 母版留档至少固定：
   - 母版主提示词
   - deny-list / 负面约束
   - 主体主色和核心高光值
   - 缺角比例和核心位置
   - 1 张最终母版
   - 比例与眼形对比板
   - 2 到 3 张失败漂移样例
6. 只有母版通过后，才进入下一关卡；如果母版不稳，不进入 S01-S08。
7. 以 v6 身份参考重新生成一张中性姿态、纯洋红工作底的角色图；去底并通过身份复核后，形成后续动画共用的 RGBA 工作母版。
8. `assets/motherboard-test/s01-s08/` 下的旧静态图全部视为历史样张，只参考原始场景意图，不复用角色像素。

### 4.3 B 关卡：S01、S08 先行关键帧验证

1. 先选择 S01、S08 做工艺覆盖验证：
   - S01 覆盖文字后置合成、眼形切换、轻微形变和叙事时序
   - S08 覆盖大幅形变、Bug 交互物、透明边缘和回弹时序
2. 选定母版后，S01、S08 必须共用：
   - 同一母版主提示词
   - 同一 deny-list
   - 同一张母版参考图
3. 按动作卡先生成 S01、S08 的关键姿态，不在这一关同时铺开其余 6 张。
4. 这一关同时测试 `同一母版在不同状态下是否仍像同一个角色` 和 `两类主要工艺是否可重复`，不再回头做大范围风格探索。
5. 生图关键帧仍然禁字；S01 的文字在合成阶段加入。
6. 对每张图做轻量修整：
   - 按洋红色距确定性去背景并输出 RGBA PNG
   - 去除边缘洋红污染，检查 Alpha 是否随帧闪烁
   - 清理杂边
   - 统一主体色相
   - 提亮或压暗核心
   - 修正缺角、眼睛、伴生像素位置
   - 如需软阴影，使用统一的独立阴影图层，不保留生成式地面投影
7. 把两组关键帧分别放到同一页里复核：
   - 是否像同一个角色
   - 缺角是否稳定
   - 核心位置是否稳定
   - 有没有混入第三层小剧情
   - 深浅背景下是否都清楚
8. 为两张先行表情补“动态复用记录”：
   - 该张允许的主形变
   - 该张允许的眼形和核心状态
   - 允许的 1 类额外信号
   - 明确禁止出现的漂移点

### 4.4 通过标准

只有在下面条件都成立时，先行关键帧阶段才算通过：

- 不看文案也能认出同一角色
- 主体没有明显漂移成别的颜色或别的比例
- S01、S08 都没有混入手脚、强道具或强场景
- 两张都只有 `1 个主语义动作`，主体、眼形和核心没有表达互相冲突的状态
- 文字、伴生像素、外部特效或必要交互物最多只使用 `1 类`
- 生图输出里没有模型直接生成的中文、英文标题、对白框或画中字
- RGBA 边缘没有白边、洋红污染、背景残留或帧间闪烁

## 5. 阶段二：首发动态制作

### 5.1 两张先行表情跑通

先不创建完整 Skill，直接手工把 S01、S08 跑到可导出的成品：

1. S01 完成关键帧修整、文字合成、眼形切换、循环和透明边缘检查。
2. S08 完成 Bug 分层、主体压扁与回弹、眼形切换、循环和透明边缘检查。
3. 每一步记录输入、输出、人工判断、可确定性执行的操作和失败原因。
4. 两张都必须经过浅色背景、深色背景、原尺寸和最小图标尺寸检查。
5. 文字合成固定使用同一 Sarasa 简体中文等宽中粗字形、深青字色和内嵌处理参数；后续 S02、S04 不再另选字体或发光样式。
6. S01 从新的 RGBA 工作母版确定性制作六帧；“不逐帧生图”不等于沿用旧 `s01-shoudao.png`。
7. S08 的最大受压锚点允许缺口左侧上沿随挤压圆润隆起；验收依据是右上缺角仍可识别，而不是简单禁止局部高点。

当前先行样片产物：

- `assets/motherboard-test/output/s01-shoudao/`
- `assets/motherboard-test/output/s08-bug-squash/`

两张样片通过自动尺寸、帧数、时长和透明边缘检查后，先进行一次联合视觉审核。审核中若调整的是身份锁、锚点判定、依赖或输出契约，先回写 Skill 规范再初始化目录；若只调整 Voxel Max 的文字位置、动作幅度或停留时间，则留在项目参数中。

### 5.2 从真实流程抽取仓库内 Skill（已完成）

S01、S08 已经跑通并通过联合审核，仓库内 `.agents/skills/animated-sticker-maker/` 已创建：

- 只固化两张样张已经证明可复用的步骤，不提前为未发生的问题设计复杂框架。
- 对外只要求 `一张静态图 + 一段自然语言提示词`；动作卡、身份锁、背景策略和导出计划全部在 Skill 内部生成。
- v1 要求输入图中有一个明确主主体；人物、宠物、吉祥物、插画、物体和 Logo 都可接受，多主体互动与镜头动画暂不承诺。
- Skill 不写死 Voxel Max 的配色、缺角、眼形、文字或八个动作；这些内容作为项目案例和测试输入存在。
- v1 只正式支持 `$imagegen` 生成后端，但切帧、RGBA 处理、合成、QA 和导出脚本保持后端无关。
- 工作底颜色根据输入主体调色板自动选择；Voxel Max 使用洋红只是项目结果，不是通用默认值。
- 将切帧、规范化、文字与特效合成、透明边缘检查、预览和导出优先做成确定性脚本。
- 通用默认输出顶层只有 `sticker.webp`；RGBA 帧和动作记录进入 `source/`，contact sheet 与检查报告进入 `qa/`，GIF 和平台文件只在 `exports/` 中按需生成。
- 平台无关的 RGBA 源帧与 `sticker.webp` 统一使用 `1024×1024` 母版画布；飞书、微信等尺寸变化只发生在平台导出目录。
- 通用时序使用 `4～8` 个独特帧和逐帧停留时间，总时长约 `1.2～2.0 秒`，不把固定视频帧率设为用户必填项。
- 将角色一致性、动作语义和失败帧判断写成明确的视觉 QA 清单。
- 暂不发布成个人 Skill 或 Plugin；首发包完成前，它属于本项目的生产工具。

当前实现包括：

- 手动触发配置：`disable-model-invocation: true` 与 `allow_implicit_invocation: false`
- 通用动作计划、透明处理、视觉 QA 和平台导出参考
- `chroma_key.py`：Pillow + NumPy 的自动工作底识别、软 Alpha 和去溢色
- `package_sticker.py`：源帧校验、动态 WebP、contact sheet、动作记录和 QA 报告打包
- S01、S08 两条真实回归路径

### 5.3 用 Skill 制作其余 6 张并同步加固

使用第一版 Skill 制作 S02、S03、S04、S05、S06、S07：

- 重复出现的人工步骤，补进脚本或工作流。
- 重复出现的漂移和失败，补进验证规则和修复路径。
- 只出现一次、依赖具体画面的审美判断保留为人工审核，不硬编码成通用规则。
- 每次修改 Skill 后，至少回归 S01 或 S08 中对应的工艺路径。

当全部 8 张通过平台导出验证后，才将仓库内 Skill 标记为 v1；第二个独立表情包验证通过后，再考虑提升为个人 Skill 或封装 Plugin。

### 5.4 动态档位

8 个首发表情全部制作动态版本：

- 微动态：S02、S03、S04、S06、S07
- 叙事动态：S01、S05、S08

### 5.5 动态约束

- 每个动作先控制在 4 到 6 帧
- 不追求长动画
- 不让每一帧都完全重新生图
- 工作帧全部使用同一洋红背景规范，去底后以 RGBA PNG 作为动画源
- 关键帧仍然要保住缺角、核心和主体色相
- 缺角不可变形到不可辨认
- 核心中心点偏移必须保持在主体中心附近，不可跑到角落
- 伴生像素只允许在主体右上附近活动，不单飞成第二主角
- 烟、扫描线、故障边缘优先视为叠层特效，不把主体本身画成另一种形状
- 静态图只作为关键帧、预览图和封面素材，不替代动态交付物
- 阴影与主体分层；阴影是否启用由平台导出配置决定

### 5.6 推荐动作类型

- 脉冲
- 扫描
- 轻微压缩回弹
- 冒烟
- 小幅抖动
- 裂开再合体

## 6. 阶段三：平台导出

平台策略保持：

> 一套创意资产，飞书首验，微信随后兼容。

执行上分两层：

- 内容层统一：角色、动作、文案、配色不拆成两套
- 验收顺序：先用飞书动态表情验证完整制作链路，再从同一组 RGBA 源帧导出微信兼容版本
- 规格层分开：按飞书、微信、小红书分别导出尺寸、格式和体积

进入导出阶段前，直接以 [当前平台导出指南](../../guides/platform-exports.md) 为准，不再临时手填待确认表。

最低执行清单：

1. S01、S08 先按飞书动态表情路线导出 `GIF`，预览图单独导出 `PNG`。
2. 两张通过后，剩余 6 张沿用同一导出配置，形成完整飞书测试包。
3. 飞书包通过后，再从同一组 RGBA 源帧导出微信兼容版本，不重新设计动作。
4. 按平台规格裁切主图、封面、图标，不在导出时才改构图。
5. 优先压测飞书 `48×48` 菜单图标；进入微信兼容阶段时再验证 `50×50` 图标。
6. 在真正提交前，再到官方页面复核一次规格有没有变动。

## 7. 当前不做的事

- 不直接做 24 张全套
- 不先做复杂长动画
- 不为不同平台设计两套不同角色
- 不一开始就做 PSD / AE 模板化工程
- 不接受每张都像不同角色的“多风格探索式量产”

## 8. 阶段性结论

当前最小闭环是：

1. 固定角色规则
2. 定义首发 8 个动作卡
3. 手工跑通 S01、S08 两张先行表情
4. 从真实流程抽取仓库内 `animated-sticker-maker` Skill
5. 用 Skill 制作其余 6 张并同步加固
6. 先导出完整飞书测试包，再导出微信兼容包

只有这一步成立，后面的 24 张扩展和量产模板才值得继续做。
