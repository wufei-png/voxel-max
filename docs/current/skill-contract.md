# `animated-sticker-maker` 产品契约 v0.6

## 1. 目标

把一张静态参考图和一段自然语言提示词转成角色一致、可循环、带透明源帧和视觉 QA 的动态表情。

当前文档记录已经收敛的公开契约。仓库级 Skill 已落地到 `.agents/skills/animated-sticker-maker/`，并完成《方芯上班中》S01-S08 与微信发布链路验证；v0.6 在既有受限 GIF / 预览 PNG、共享调色板和完整审核门禁之上，补齐包内帧路径规范化、可选高帧率渲染轨、显式帧率降级与最低调色板质量线，并增加不依赖具体主体的回归测试。飞书不再是当前发布目标，也不构成版本门槛；待 `pixel-human` 完成第二主体的代表性动态试片后，再评估标记为 v1。

公开名称固定为 `$animated-sticker-maker`。它是仅手动触发的 Skill：只有用户显式调用该名称时才加载，不根据普通图片、GIF 或动画请求自动触发。仓库通过 `agents/openai.yaml` 的 `policy.allow_implicit_invocation: false` 关闭隐式调用入口；`SKILL.md` 不使用未被校验器支持的私有 frontmatter 字段。

## 2. 必填输入

公开调用只有两个必填输入：

1. `reference_image`：一张静态参考图。
2. `prompt`：描述目标表情、动作、文字、循环或平台的自然语言提示词。

示例：

```text
<reference_image>
让它先显示“收”，再显示“到”，最后开心地轻弹一下并循环。
```

下面这些都不是用户必填项：

- 动作卡或关键帧 JSON
- 角色身份清单
- 遮罩和图层文件
- 工作底颜色
- 帧率、画布和编码参数
- 平台导出配置

用户可以在提示词里覆盖默认值，但不需要理解内部结构。

### 2.1 输入图范围

v1 要求一张图中存在一个明确主主体：

- 支持人物、宠物、吉祥物、插画角色、物体和 Logo。
- 允许复杂背景，Skill 先识别并提取主主体。
- 多主体图片只有在提示词明确指定动画对象时才继续；没有指定时询问一次。
- 不承诺多人互动、完整场景动画或镜头运动。

这一边界描述的是稳定承诺，不限制后续实验性扩展。

## 3. 内部派生信息

Skill 从两个输入内部派生：

1. 身份锁：轮廓、调色板、材质、面部锚点、固定标志和禁止漂移项。
2. 动作卡：主语义、主体形变、表情变化、附加信号、锚点帧和循环方式。
3. 生成分工：哪些新姿态需要生图，哪些变化由变形、位移、透明度或图层合成完成。
4. 透明策略：直接使用 Alpha，或根据主体颜色自动选择高色距工作底后确定性去底。
5. QA 计划：身份一致性、动作语义、Alpha 边缘、帧间稳定、循环接缝和导出约束。

角色签名轮廓必须结合母版判断。

交互物与主体发生物理接触时，接触位置必须由交互物覆盖范围内的局部轮廓决定；曲面、缺角和受压形变不能使用主体全局 bbox 代替接触面。

生成锚点如果整体身份漂移，只允许在以下条件同时满足时抢救局部组件：主体仍使用已经批准的稳定锚点；局部边界可确定性提取；不会留下接缝、重复特征或源图残片；动作计划明确记录组件源、批准底图和提取方式。被拒绝的整图不能改名当作批准锚点。

## 4. v1 能力边界

- 主体范围：单一明确主主体；多主体互动和镜头动画不在稳定承诺内。
- 生成后端：只正式支持 `$imagegen`。
- 后处理：切帧、规范化、RGBA、文字与特效合成、循环、预览和导出使用确定性脚本。
- 角色规则：通过输入分析和项目案例提供，不写死 Voxel Max。
- 平台：未指定时输出通用资产；指定平台时加载相应导出规则。
- 平台导出：从聚合状态、自动审核（或非空且全为真的结构化 `checks`）和视觉审核均通过的 RGBA 源帧生成派生文件，仅有顶层 `status: pass` 不足以放行；不从已压缩 WebP 二次转码。受限 GIF 使用跨帧共享调色板并选择满足体积上限的最高候选色数，失败时不得静默删减语义帧。默认使用 4～8 张语义关键帧；只有包内存在单独通过时序与视觉审核的确定性高帧率渲染轨时，才可显式指定按帧率候选和最低色数质量线自适应导出。`--allow-unreviewed` 只用于显式诊断，不得生成发布交付物。
- 演进：第二个独立主体完成代表性试片后再评估 v1；只有真实出现第二种生成后端需求时才抽象多后端接口。

## 5. 开源要求

- 不包含用户机器绝对路径或私有项目依赖。
- 核心脚本使用可公开安装的依赖。
- 核心图像处理优先使用 Pillow 与 NumPy，避免把 OpenCV 及其本地 ABI 兼容性设为运行前提。
- 自动色键模式必须覆盖实测边框色差，不能因调用方传入过低阈值而留下非透明画布边缘。
- 字体、模板和示例资产必须具备可再分发许可，或改为用户可配置输入。
- Voxel Max 作为回归案例存在，但不能成为运行前提。

## 6. 默认输出契约

用户没有指定平台或格式时，只在顶层交付一个高质量透明动画 WebP；源文件、QA 和平台导出分层存放：

```text
output/<name>/
├── sticker.webp
├── source/
│   ├── frames/
│   │   ├── 000.png
│   │   ├── 001.png
│   │   └── ...
│   ├── rendered-frames/      # 可选；经过独立审核的高帧率派生轨
│   └── motion.json
├── qa/
│   ├── contact-sheet.png
│   └── report.json
└── exports/                  # 仅指定平台或格式时出现
    └── <platform>/
```

- `sticker.webp`：默认可用成品，保留完整 Alpha 和较高颜色质量。
- `source/frames/`：RGBA PNG 源帧，用于继续编辑和复现。
- `source/motion.json`：记录提示词解析后的动作计划和帧时序，不要求用户手写。
- `source/rendered-frames/`：仅在确定性插帧或合成能明显提升运动表现时存在；必须由 `motion.render` 记录帧目录、帧数、逐帧时长和总时长，并具备独立通过的自动/检查与视觉审核报告。它不替代语义关键帧。
- `qa/contact-sheet.png`：把所有帧按相同比例排列，供 Skill 检查身份漂移、基线、边缘和异常帧；它不是成品，也不能替代动画回放。
- `qa/report.json`：记录自动检查结果和人工视觉结论。
- `exports/`：仅在提示词指定平台或格式时创建。

默认不生成 `preview.gif`。GIF 颜色和透明边缘受格式限制，只在用户明确要求或目标平台需要时导出。

### 6.1 默认画布

- `source/frames/*.png` 与 `sticker.webp` 统一使用 `1024×1024` RGBA 画布。
- 主体保持原比例放入正方形画布，不拉伸、不裁掉突出部位，默认保留约 `8%～12%` 透明安全区。
- 平台尺寸、轻量预览和体积压缩只在 `exports/<platform>/` 中处理，不改变平台无关母包。
- 提示词明确指定尺寸时，可以覆盖该默认值。

重新打包会覆盖自动 QA 报告，并把视觉审核重置为待处理。源帧发生变化后不得沿用旧的人工通过结论，必须重新完成并写回视觉 QA。

打包时把工作目录中的帧复制为 `frames/000.png`、`frames/001.png` 等规范路径，并同步改写动作条目和匹配的语义停留帧引用。交付包的 `source/motion.json` 不得依赖工作目录中的原始文件名或绝对路径。

### 6.2 默认时序

- 不使用固定视频帧率作为公开默认值；动画由 `4～8` 个独特帧和各自停留时间组成。
- 总时长根据动作控制在约 `1.2～2.0 秒`。
- 普通过渡帧通常停留 `80～160 ms`；最能表达语义的终态停留约 `400～700 ms`。
- `source/motion.json` 为每帧记录 `duration_ms`，快速抖动可以使用短帧，文字阅读和表情终态使用长帧。
- 默认循环；提示词明确要求只播放一次时才关闭循环。

可选高帧率渲染轨不改变上述公开默认值。平台导出若需要在体积限制下自适应，必须显式给出从高到低的候选帧率与最低可接受色数；每个帧率先尝试到色数质量线，再降到下一帧率，所有尝试和最终选择写入导出报告。

### 6.3 小尺寸验收

- `50×50` 用于压力测试角色签名轮廓、主表情和主语义信号，不要求较长文字在该尺寸下仍能逐字精确阅读。
- 精确文字必须在目标平台的实际最小显示尺寸下可读；平台显示尺寸尚未核实时，将文字可读性记为平台 QA 待办，不用 `50×50` 代替。
