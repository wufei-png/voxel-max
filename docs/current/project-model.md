# 多主体表情项目模型

本文档定义仓库中跨主体生效的组织规则。主体特有的身份、动作和阶段决定由 `projects/<subject>/` 下的文档负责。

## 1. 层级

```text
仓库
└── 主体项目（一个稳定主体）
    ├── 身份规范
    ├── 一个或多个批准母版
    └── 零个或多个表情包
        └── 多个表情
```

- 一个主体可以使用多个互补母版，也可以拥有多套表情包。
- 一套表情包只属于一个主体。多主体共同出演暂不属于稳定生产边界。
- 风格通过身份规范或独立风格规范描述，不把“风格”和“母版”混为同一概念。
- `S01` 等编号限定在一套表情包内部；跨包引用必须带主体与表情包 ID。

## 2. 标准目录

目录按需创建，不为尚未发生的阶段预建空文件夹。

```text
projects/<subject>/
├── README.md                  # 状态、公开名、最小阅读路径
├── identity/
│   ├── spec.md               # 身份与风格真值
│   ├── masters/              # 已批准身份母版
│   └── references/           # 辅助结构参考，不等于母版
├── research/                 # 尚未转化为决定的研究材料
├── packs/
│   ├── README.md             # 未命名系列的规划入口，可选
│   └── <pack>/
│       ├── README.md         # 包状态、清单、生产与发布入口
│       ├── motion-spec.md    # 本包动作卡
│       ├── generation-guide.md
│       ├── scripts/          # 只服务本包的确定性脚本
│       ├── work/             # 中间资产
│       ├── output/           # 平台无关源包
│       └── releases/         # 平台发布包
└── archive/                  # 仅供追溯的主体历史
```

## 3. 归属规则

- 根 `README.md` 只说明仓库范围和入口。
- 根 `AGENTS.md` 只记录 Agent 行为、阅读和归属规则。
- 根 `CONTEXT.md` 只统一跨项目领域语言。
- `docs/current/` 只保存项目模型、通用 Skill 契约等跨主体决定。
- `docs/guides/` 只保存跨主体操作指南；主体或表情包专用指南必须就近存放。
- 通用算法与平台导出能力属于 `.agents/skills/animated-sticker-maker/`；写死主体锚点、动作、文字或发布文案的脚本属于对应表情包。
- 研究材料、概念参考和被拒绝的产物没有当前决策权。

## 4. 命名与状态

- 目录使用稳定、ASCII、`kebab-case` 的内部 ID；公开名称记录在主体或表情包 README 中。
- 未命名主体可以先使用稳定内部 ID，但必须明确标记“公开名待定”。
- 主体至少区分 `concept`、`planning`、`production`、`completed`；表情包独立记录自己的状态。
- “母版”只用于已经审核通过的身份基准。只有概念参考时，不创建虚假的身份规范或表情包生产目录。
- 完成的表情包保持语义清单和发布版稳定；后续主题建立新表情包，不把旧包无边界扩写。

## 5. Agent 最小读取

Agent 先从 [`../README.md`](../README.md) 找到任务所属主体，再读取该主体 README。制作某套表情时，只补充读取该主体身份规范、该包 README、动作卡和当前操作所需指南；不得默认加载其他主体的视觉规则。
