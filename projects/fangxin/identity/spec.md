# 方芯（Voxel Max）身份规范 v1

本文档只定义方芯跨表情包保持稳定的身份、视觉语言和表达通道。具体系列主题、表情清单、动作与发布状态由对应 `packs/<pack>/` 文档负责。

## 1. 主体身份

- 中文公开名：`方芯`。
- 英文 / IP 名：`Voxel Max`。
- 核心定位：一个正在帮你干活、但会卡住、发热、装死和出现故障状态的小方块 AI 主体。
- 基础体型：圆角正方体，常态无手脚、无嘴、无眉毛。
- 出图语言：2.5D 正视风格，以柔和稳定的厚片感表达体积，不使用强透视或扁平 2D。

## 3. 固定身份签名

识别优先级固定为：

1. 右上向内缺角
2. 双眼之间的发光圆角方形状态核心
3. 青绿色圆角方块本体与 2.5D 材质
4. 本体形变语法
5. 伴生像素、文字或交互物

硬规则：

- 缺角永久位于右上。主体可以受压、拉伸或轻微转动，但关键帧中仍须可辨。
- 缺角与外轮廓使用同一套圆润语言；内圆角约为外角视觉半径的 `35%～50%`。
- 状态核心占据鼻位但不是鼻子、嘴或任意屏幕，外部圆角方框永久存在。
- 状态核心两侧是具有统一厚度、深色材质和高光的实体眼部模块，不贴扁平颜文字。
- 主体色相不因情绪或状态整体切换；语义颜色只作用于核心、伴生像素、警告符号或故障边缘。
- 长方体只能是单张表情中的临时形变，不是常态身份。

## 4. 形变与表达

- 每张表情只有一个主语义动作；主体形变、眼形和状态核心必须共同服务该动作。
- 眼部模块和状态核心是基础表达通道。文字、伴生像素、外部特效或必要交互物最多再选择一类。
- 不增加与主语义无关的道具、场景或拟人化小故事。
- 交互物与主体发生物理接触时，接触位置必须按局部轮廓确定，不能用主体全局包围框代替接触面。
- 主体被压缩或拉伸时，核心外框只允许约 `5%～8%` 的同步弹性形变。

常用眼形：

| 状态 | 眼形 |
| --- | --- |
| 常态 | 母版圆角方眼和小高光 |
| 开心 / 确认 | 常态眼包围框内的实体 `^ ^` |
| 不耐烦 / 工作中 | 纵向压缩的半闭横眼 |
| 专注 / 思考 | 接近常态尺寸，轻微收窄并向内倾斜 |
| 用力 / 卡住 | 常态眼包围框内的实体 `> <` |
| 休眠 / 装死 | 低亮度细横线眼 |

所有眼形保持相同材质、厚度和边缘语言，不超出常态眼最大包围框。

## 5. 配色

| 用途 | 色值 |
| --- | --- |
| 主体 | `#62E6D8` |
| 主体阴影 | `#0F6E67` |
| 核心高光 | `#E7FFFB` |
| 深背景辅助边 | `#C8FFFA` |
| 成功 | `#74F26A` |
| 警告 | `#FFD24A` |
| 报错 / 过载 | `#FF5C57` |

颜色分为三层：主体与缺角属于身份锚点层；明度、饱和度、核心亮度和阴影强度属于微变层；红、绿、黄和故障错位属于语义层。故障可以使用轻量 RGB 错位边缘，但不改变主体底色。

状态不能只靠颜色表达；状态色必须与符号、亮度节奏或运动方式至少组合一种。

## 6. 状态核心与伴生像素

- 核心内部光场可以脉冲、收缩、分段、改变亮度或显示单一简单符号。
- 核心每帧最多显示一个简单字符或系统符号，不显示完整单词、句子或复杂 UI。
- 青白表示正常或处理中，绿色表示完成，黄色表示等待或警告，珊瑚红表示过热或错误，暗灰青表示休眠或装死。
- 状态核心是唯一主发光源；身体文字和其他信号不得争夺视觉中心。
- 伴生像素默认最多一组，可以根据动作变成单点、三点或旋转点，但不发展为第二个辅助角色。

## 7. 文字规则

- 文字只在动作语义不足时按需使用，不给每张表情添加固定标题。
- 精确文字由后期确定性合成，生图阶段禁止模型直接生成中文、英文标题、对白框或画中字。
- 身体内嵌字使用偏方正的等宽无衬线中粗字形、深青色和轻微内凹质感，不发光。
- 每套表情包负责决定具体文字、位置、时序和字体许可。

## 8. 透明与小尺寸

- 最终源资产必须是 RGBA 透明主体，不烘焙白底、工作底、地面投影或环境反射。
- 如使用高色距纯色工作底，必须确定性去底并检查边缘污染；工作底颜色不是身份配色。
- 阴影如有必要，作为独立后期图层加入，同一动作各帧不得重新生成不同阴影。
- 浅色背景依靠主体阴影与核心对比；深色背景可以增加极轻冷色辅助边或外发光。
- 核心和缺角在聊天小尺寸、浅色与深色背景下都必须可辨。

## 9. 默认禁止方向

- 不使用 Minecraft、8-bit 复古游戏或普通扁平 App 图标语言。
- 不把紫色或高饱和纯蓝作为主体主色。
- 不在一张表情中叠加裂开、扫描、加载、旋转、冒烟等多套主动作。
- 不默认增加手脚、嘴、眉毛、复杂 UI、完整场景或第二主体。

未来表情包如要突破某项默认限制，必须先说明为何仍能保持方芯身份，并在该包 README 中记录局部例外；不能静默修改本规范。

## 10. 身份验收

1. 抽掉文案和道具后仍能认出方芯。
2. 缺角、状态核心、主体色相、眼距和材质语言跨帧稳定。
3. 形变后没有出现身份结构翻转、凭空新增特征或比例换人。
4. 主动作一眼可懂，没有第三层剧情。
5. RGBA 边缘在浅色和深色聊天背景上没有白边、工作底污染或闪烁。
6. 小尺寸下仍能分辨主体轮廓、缺角和主表情。
