# 首发动态动作卡 v1

本文档只定义《方芯上班中》S01-S08 的动作语义、逐帧意图、循环和禁止项。角色身份与视觉规则以 [`../../identity/spec.md`](../../identity/spec.md) 为准。

## 1. 使用范围

角色身份、颜色、状态核心、眼部模块和文字规则以 [方芯身份规范](../../identity/spec.md) 为准；生图提示以 [本包生成指南](generation-guide.md) 为准。

所有表情使用同一母版：

`projects/fangxin/identity/masters/fangxin-v6.png`

该文件用于锁定身份；实际动画统一从基于 v6 重新生成并去底的新 RGBA 工作母版开始。旧 `s01-s08/*.png` 只作为历史样张，不进入成品帧。

## 2. 全局规则

- 每个表情使用 `4～6` 个关键帧，总时长优先控制在约 `1.2～2.0 秒`。
- 不逐帧重新发明角色。先生成或确认关键姿态，再用变形、位移、透明度和图层合成中间帧。
- 缺角、主体色相、眼距和状态核心位置在所有帧中保持可识别。
- 文字、状态符号、点动画和可独立叠加的局部特效统一后期合成。
- S01、S02、S04 统一使用深青色、等宽中粗、轻微内凹的机身文字；文字不发光，状态核心保持唯一主发光源。
- S04-S06 的状态色只覆盖核心内侧发光面；四周 3D 结构框保持母版材质与青色，只允许出现低强度、对称的淡光晕。
- 每帧主体以 RGBA 保存；生成阶段的纯洋红工作底必须完全去除，地面阴影只能作为独立后期图层加入。
- 叙事动态的最终语义帧应停留约 `400～700 ms`；回到首帧前使用短过渡，避免无意义跳变。
- 循环时不得出现角色突然换比例、核心瞬移、缺角消失或光照方向翻转。

## 3. S01 收到

- 动态档位：叙事动态
- 目标语义：明确确认已收到，同时表现积极、友好的完成反馈。
- 主形变：极轻微确认式压缩回弹。
- 眼形：常态方眼 → 实体 `^ ^` 眼。
- 状态核心：青白常亮，只做一次短促提亮；不显示“收”“到”。
- 文字：核心下方左“收”右“到”，使用统一的深青色内嵌字形。

| 帧 | 画面 |
| --- | --- |
| 1 | 常态眼，无文字，身体稳定，核心常亮。 |
| 2 | 左侧“收”出现，核心轻微提亮。 |
| 3 | 右侧“到”出现并保留“收”，两个字同时可读。 |
| 4 | 身体向下压缩约 `3%`，双眼开始闭合。 |
| 5 | 身体向上回弹约 `4%`，双眼形成实体 `^ ^`，文字保持，停留主语义帧。 |
| 6 | 身体回到基线，文字淡出，眼睛回到常态后衔接首帧。 |

- 禁止：把文字放进核心；让“到”覆盖“收”；加入勾、手势、对白框或第二次庆祝特效。
- 验收：不看文件名也能读到“收到”；最终帧缩小后仍能看清左“收”右“到”。

## 4. S02 别催

- 动态档位：微动态
- 目标语义：正在工作，但对催促有轻微不耐烦。
- 主形变：一次很轻的下沉回弹。
- 眼形：正式发布版前三帧保持常态方眼，完成一次下沉回弹后在第 4 帧收束为实体半闭横眼。
- 状态核心：青白色缓慢脉冲。
- 文字：核心下方居中显示深青色内嵌 `WORKING`，句点从暗到亮逐个变化。

| 帧 | 画面 |
| --- | --- |
| 1 | `WORKING` 无点，保持常态方眼，核心低亮。 |
| 2 | `WORKING.`，身体下沉约 `2%`，保持方眼，核心略亮。 |
| 3 | `WORKING..`，身体开始回到基线，保持方眼。 |
| 4 | `WORKING...`，身体回到基线，核心达到最高亮度，双眼收束为半闭横眼。 |
| 5 | `WORKING...` 与半闭横眼短暂停留，然后循环回无点状态和方眼。 |

- 禁止：绕主体一整圈的加载环；侧身逃跑；愤怒眉毛；进度条、弹窗或额外 UI。
- 验收：第一眼读到“仍在工作”，第二眼才读到“不耐烦”；不能像 S03“思考中”。

## 5. S03 思考中

- 动态档位：微动态
- 目标语义：安静、持续地处理信息。
- 主形变：身体完全稳定。
- 眼形：轻微收窄、向内倾斜的专注眼。
- 状态核心：青白色由低到高脉冲。
- 伴生像素：右上方依次出现三个小方点。

| 帧 | 画面 |
| --- | --- |
| 1 | 核心低亮，右上无思考点。 |
| 2 | 第一个小方点出现。 |
| 3 | 第二个小方点出现，核心亮度上升。 |
| 4 | 第三个小方点出现，核心达到最高亮度。 |
| 5 | 三个点一起淡出，核心回到低亮后循环。 |

- 禁止：传统圆形省略号；文字；身体漂浮；扫描线；加载环。
- 验收：三个方点位于角色右上附近，不单飞成第二角色；循环不产生位置跳变。

## 6. S04 跑通了

- 动态档位：微动态
- 目标语义：任务成功完成，补齐首发包的正向闭环。
- 主形变：一次短促压缩和向上轻弹。
- 眼形：常态方眼 → 实体 `^ ^` 眼。
- 状态核心：青白 → 绿色，保持完整光场，不显示勾或文字。
- 文字：核心下方居中显示深青色内嵌 `DONE`，整个单词一次性渐现；文字本身不变绿。

| 帧 | 画面 |
| --- | --- |
| 1 | 常态眼，无文字，核心青白，身体稳定。 |
| 2 | 核心转为绿色并提亮，身体向下压缩约 `3%`。 |
| 3 | 身体开始回弹，双眼开始闭合，`DONE` 以约 `40%` 不透明度整体出现。 |
| 4 | 身体向上轻弹约 `5%`，形成实体 `^ ^` 眼，`DONE` 完全可读。 |
| 5 | 身体回到基线，绿色核心、`DONE` 和 `^ ^` 眼保持，停留主语义帧。 |
| 6 | `DONE` 整体淡出，核心淡回青白，眼睛回到常态后循环。 |

- 禁止：勾形、逐字母出现、奖杯、纸屑、火箭、尾迹或第二层庆祝动画。
- 验收：缩小后 `DONE` 仍可读；首先读到“完成”，而不是只有“开心”。

## 7. S05 卡住了

- 动态档位：叙事动态
- 目标语义：角色确实被物理结构卡住，并在持续挣扎。
- 主形变：主体被左右两个短夹轨局部挤压，轻微横向压缩和纵向鼓起。
- 眼形：实体 `> <` 眼。
- 状态核心：黄色，使用断续脉冲。
- 场景元素：只保留左右两段短夹轨，不画完整房间、地板或纵深网格。

| 帧 | 画面 |
| --- | --- |
| 1 | 主体已卡在短夹轨之间，位于中线，核心低亮黄色。 |
| 2 | 主体向左挣扎约 `2%～3%`，形成实体 `> <` 眼。 |
| 3 | 回到中线，核心短暂熄一下。 |
| 4 | 主体向右挣扎约 `2%～3%`，核心重新亮起。 |
| 5 | 回到中线并短暂停顿，保持被夹状态后循环。 |

- 禁止：恢复成完整房间式卡槽；大面积白墙；楼梯、地板、透视空间；让主体成功脱困。
- 验收：第一眼读到“卡住”，夹轨只是局部约束，不比角色更抢眼；缺角仍清楚。

## 8. S06 CPU 烧了

- 动态档位：微动态
- 目标语义：处理过载、发热，但不是爆炸或起火。
- 主形变：主体轻微鼓胀再恢复，最大不超过约 `3%`。
- 眼形：疲惫的半闭横眼。
- 状态核心：青白 → 黄色 → 珊瑚红，再回落。
- 特效：头顶正中只出现一组烟柱，内部由三条轻烟丝组成；烟根与头部轻微重合，不能变成三个彼此分离的烟团。

| 帧 | 画面 |
| --- | --- |
| 1 | 半闭横眼，核心青白，身体稳定。 |
| 2 | 身体轻微鼓胀，核心转黄。 |
| 3 | 核心转为珊瑚红并快速提亮，头顶正中开始冒出短烟丝。 |
| 4 | 单组烟柱展开成三条较长、低透明度的 S 形烟丝；烟根压入头顶约十几像素，主体开始恢复，核心保持红色。 |
| 5 | 烟淡出，核心由红回到青白，身体回到基线后循环。 |

- 禁止：明火、爆炸、温度计、多组分离烟团、实心灰色云帽、焦黑表面、报错弹窗。
- 验收：能读到“过热”，但主体主色相没有变红；烟柱位于头顶正中，在透明背景上边缘干净，聊天尺寸下仍能看出三条烟丝。

## 9. S07 已读但装死

- 动态档位：微动态
- 目标语义：维持现有趴平装死造型，只通过偷偷睁眼暴露“已读”。
- 主形变：始终保持趴平压薄，不在循环中重新站起。
- 眼形：双横线眼；画面右眼必须先清除原横线像素，再把同一眼部模块纵向变形，不能叠加第二层半透明眼睛。最大可见眼体约为常态方眼高度的一半，并同步放大、提亮高光。
- 状态核心：保持近乎熄灭，只留最弱识别光。

| 帧 | 画面 |
| --- | --- |
| 1 | 趴平，双横线眼，核心近乎熄灭。 |
| 2 | 画面右眼从横线长成较窄眼缝，同时出现一个较小高光。 |
| 3 | 画面右眼继续长高到常态方眼高度的约 `50%`，高光同步变大、变亮。 |
| 4 | 右眼重新闭合。 |
| 5 | 维持装死状态短暂停留后循环。 |

- 禁止：重新站起；大幅呼吸；文字“已读”；两个眼睛同时睁开；右眼超过常态方眼高度的一半；核心重新点亮。
- 验收：整体第一眼仍是装死，播放后能看清画面右眼本身的实际高度变化和增强高光；最大可见眼体约 `32 px`，对应常态方眼 `64 px` 的一半；睁眼帧不得残留底层横线或双重轮廓。

## 10. S08 被 Bug 压扁

- 动态档位：叙事动态
- 目标语义：一个明确的 Bug 从上方压下，角色被压扁后回弹。
- 主形变：主体受压到正常高度的约 `60%～65%`，不压成无法容纳状态核心的纸片。
- 眼形：受压时形成压缩版实体 `> <` 眼，最扁时变为短横眼。
- 状态核心：青白略降亮度，外框保持近似方形，只做允许范围内的轻微弹性形变。
- Bug：深灰简化虫体，增加两只极小的青白眼点，用于明确正面方向，不赋予夸张表情。

| 帧 | 画面 |
| --- | --- |
| 1 | 主体接近常态，Bug 从上方进入画面。 |
| 2 | Bug 接触主体顶部，角色眼睛开始挤压。 |
| 3 | Bug 下压，主体明显变矮，形成实体 `> <` 眼。 |
| 4 | 主体达到最扁状态，眼睛变成短横眼；Bug 的两只小眼短暂眨一下，停留主语义帧。 |
| 5 | Bug 稍微抬起，主体回弹一半。 |
| 6 | Bug 回到起始高度，主体恢复后衔接首帧。 |

- 禁止：多只虫；虫子长嘴或变成第二萌宠；错误符号、爆炸、故障彩边；把状态核心压成长条。
- 验收：Bug 一眼可辨且有方向感，角色仍是画面主角；最扁帧的缺角和核心仍可识别。

## 11. 集中审核清单

审核首发包时只检查下面这些决策：

1. S01 的“收”“到”位置、先后顺序和最终 `^ ^` 眼是否成立。
2. S02 是否先保持方眼，再在运动完成后收束为眯眼。
3. S03 的右上三个方点是否和 S02 的文字点动画充分区分。
4. S04 的绿色核心、整体渐现 `DONE` 与轻弹是否足够表达“跑通了”。
5. S05 的短夹轨是否比原来的房间式卡槽更清楚。
6. S06 是否只保留一组头顶正中的轻烟丝，避免演成爆炸。
7. S07 是否维持趴平，只让单眼偷看。
8. S08 的 Bug 小眼是否足以辨认方向，又没有抢主角。
