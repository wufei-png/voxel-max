# 方块表情包出图提示 v1

这是《方芯上班中》的历史可复现生成指南，不单独定义角色或动作。开始前读取 [`../../identity/spec.md`](../../identity/spec.md) 和 [`motion-spec.md`](motion-spec.md)。

## 1. 使用原则

- 先读 [方芯身份规范](../../identity/spec.md)，再出图。
- 所有提示都默认服务于同一个角色，不重新发明角色。
- 每次只表达 `1 个主语义动作`，主体形变、眼形和状态核心必须共同服务这个动作。
- 文字、伴生像素、外部特效或必要交互物最多只选 `1 类`；不要叠加第二类额外信号。
- 不加复杂背景，不加第二角色，不加手脚，不加多余道具。
- 生图阶段统一禁字：不要文字、不要中文、不要英文标题、不要对白框；S01、S02、S04 的内嵌状态字由后期确定性合成。

## 2. 固定身份块

```text
严格以 projects/fangxin/identity/masters/fangxin-v6.png 为角色身份参考。一个圆角正方体 AI 小方块角色，2.5D 正视构图，带柔和稳定的厚片感，右上角固定缺角，双眼之间有发光状态核心，两侧是深色实体眼部模块，主体主色固定为 #62E6D8，阴影偏深青绿，核心高光偏白青，半软体数字材质，允许轻微物理形变，纯色洋红 #FF00FF 工作背景，背景颜色均匀，无地面，无投影，无环境反射，无背景光晕，构图居中，单角色
```

## 3. deny-list 块

每次出图都建议追加下面这段短约束：

```text
保持同一个角色设定，缺角必须清晰可见，主体色相不要漂移，核心位置稳定，不要紫色主色，不要高饱和纯蓝，不要 Minecraft 或 8-bit 复古游戏风，不要普通 app icon 风，不要复杂 UI 面板，不要第二角色，不要强场景叙事，不要手脚，不要多重动作叠加，不要文字，不要中文，不要对白框，不要标题，不要白色背景，不要渐变背景，不要地面，不要投影，不要背景反光，不要洋红色映到主体上
```

## 4. 母版验证提示

母版验证阶段只测试角色稳定性，不测试复杂动作。

推荐拼法：

```text
[固定身份块]
角色保持静止或只做极轻微姿态变化，只验证轮廓、缺角、核心、材质和小尺寸识别度，不测试复杂动作
[deny-list 块]
```

母版阶段额外要求：

- 3 组候选之间只允许材质、阴影、渲染细节有差别。
- 不允许直接混入扫描、冒烟、裂开、加载圈、网格卡住等状态动作。
- 选定母版后，把同一张通过图作为 S01-S08 的统一参考图。
- v6 白底图只作为身份参考；动作关键帧统一使用纯洋红工作背景，去底后保存 RGBA PNG。
- 在制作 S01 前，先以 v6 重新生成中性姿态的洋红工作底，并去底形成新的 RGBA 工作母版；旧 `s01-s08/s01-shoudao.png` 不作为动画源。

## 5. 状态增量块写法

每张图只补这次允许变化的部分：

- `主形变`：这张图的唯一主体变形
- `主状态特效`：这张图最主要的状态信号
- `额外信号`：按需从文字、伴生像素、外部特效或必要交互物中选择 1 类

推荐拼法：

```text
[固定身份块]
[该张的主形变]
[该张的主状态特效]
[可选的额外信号]
[deny-list 块]
```

## 6. 首发 8 个表情关键帧提示

S01-S08 阶段默认前置条件：

- 已先完成母版验证
- 已固定同一母版主提示词
- 已固定同一 deny-list
- 已固定同一张参考图

### 6.1 收到

S01 不沿用旧静态图。它从新的 v6 RGBA 工作母版开始，后续六帧通过确定性形变、眼形替换、核心亮度和文字图层完成，不让模型逐帧重画角色。

```text
主形变：轮廓保持稳定，只做极轻微确认式回弹。
主状态特效：为后期状态字保留清楚、平整的正面区域。
```

后期合成：使用统一的 Sarasa 简体中文等宽中粗字形和深青色内嵌质感；在核心下方的身体正面区域，左侧先出现“收”，右侧再出现“到”并保留“收”。两个字不发光、不进入状态核心。最终双眼变成实体 `^ ^` 眼。

### 6.2 别催

```text
主形变：主体保持正面，只有一次很轻的下沉回弹。
主状态特效：双眼纵向压缩成实体半闭横眼，状态核心保持青白色缓慢脉冲。
```

后期合成：使用统一的等宽中粗字形，在核心下方居中加入深青色内嵌 `WORKING…`；`WORKING` 保持深青，三个点从暗到亮依次变化。不要生成绕主体一整圈的加载环，不让生图模型直接生成英文。

### 6.3 思考中

```text
主形变：无明显形变，轮廓整体稳定。
主状态特效：双眼轻微收窄并向内倾斜，状态核心由低到高缓慢脉冲。
额外信号：角色右上附近依次出现 3 个小方形思考点。
```

### 6.4 跑通了

```text
主形变：主体先向下压缩约 3%，再向上轻弹约 5%。
主状态特效：状态核心由青白转为绿色并保持完整光场，双眼最终变成实体 ^ ^ 眼；为后期状态字保留清楚、平整的正面区域。
```

后期合成：使用统一的等宽中粗字形，在核心下方居中加入深青色内嵌 `DONE`；整个单词一次性由透明渐现到完全可读，不逐字母出现。成功绿色只由核心承担。不要再向核心加入勾形，也不要加入尾迹或第二层庆祝特效。

### 6.5 卡住了

```text
主形变：主体已经卡在左右两个短夹轨之间，局部横向压缩并轻微纵向鼓起，只做小幅左右挣扎。
主状态特效：双眼形成实体 > < 眼，状态核心为黄色断续脉冲。
```

不要完整房间、地板、白墙、楼梯或纵深网格，只保留局部短夹轨。

### 6.6 CPU 烧了

```text
主形变：主体轻微鼓胀，最大不超过约 3%，随后恢复。
主状态特效：顶部只冒出一缕与主体接触的烟，双眼保持疲惫半闭横眼。
基础状态：状态核心由青白转黄，再转为珊瑚红。
```

### 6.7 已读但装死

```text
主形变：方块始终趴平压薄，不在循环中重新站起。
主状态特效：双眼为细横线，其中右眼短暂睁开一条带微弱高光的窄缝。
基础状态：状态核心始终近乎熄灭。
```

### 6.8 被 Bug 压扁

```text
主形变：被一个深灰简化 Bug 从上方压到正常高度的约 60%～65%，随后回弹。
主状态特效：受压时双眼由实体 > < 眼压成短横眼；Bug 正面有两只极小青白眼点。
基础状态：状态核心略降亮度，外框仍保持近似方形。
```

不要多只虫、错误符号、爆炸、故障彩边，不要把 Bug 萌化成第二主角。

## 7. 组合示例

下面是实际投喂模型时的推荐拼法：

```text
[固定身份块]
主形变：主体轻微鼓胀。
主状态特效：顶部冒出少量烟。
基础状态：核心偏红。
[deny-list 块]
```

## 8. 复核清单

出图后逐张检查：

1. 缺角是不是还在右上，而且一眼可见
2. 主体是不是还保持同一色相
3. 有没有偷偷长出手脚
4. 有没有加复杂背景或额外道具
5. 一张图里是不是只有 1 个主语义动作，主体、眼形和核心是否共同服务它
6. 文字、伴生像素、外部特效或必要交互物是不是最多只用了 1 类
7. 有没有模型自己画出的中文、英文标题、对白框或画中字
