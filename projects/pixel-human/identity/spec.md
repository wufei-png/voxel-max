# 像素小人身份规范

- 状态：`identity_locked`
- 母版状态：`approved_v1`
- 公开名：像素小同事

本文档是 `pixel-human` 当前身份与视觉规则的唯一真值。研究报告只保留为决策来源；若报告建议与本文冲突，以本文为准。

## 1. 定位

像素小人是一个面向现代工作聊天、略带技术气质的**无脸冷面工作搭子**。它以克制、略慢、带干幽默的反应建立人格，不是方芯的人形皮肤，也不是常规 RPG 或软萌像素头像。

角色默认代表发送者本人。首发优先服务微信，但身份母版、透明源帧和动作语义保持平台中立；正式导出时再核实目标平台实时规则。

用户已确认 [`../references/original-avatar.png`](../references/original-avatar.png) 的重绘、改编、公开发布与商用权利完整，权利链不构成当前阻塞项。

## 2. 身份锚点

### 2.1 固定项

1. 黑色硬边块状头发，顶部近水平，左侧保留台阶式下切。
2. 暖米色大面积脸区，**始终不出现眼、眉、鼻、嘴或状态屏幕**。
3. 正面大头半身构图，脸区是第一识别面，肩线宽于头部。
4. 冷紫色宽肩上衣，只保留两层肩部阶梯；中央黑色垂直中缝固定为 4 个逻辑像素宽。
5. 硬边、有限色板、整像素几何；透明边缘只允许完全透明或完全不透明。

### 2.2 可变项

- 头部可做 1–2 像素的倾斜、俯仰或受控伪 3/4 转向。
- 伪 3/4 状态下，脸区最多收窄 1–2 像素，左侧台阶发块仍须可辨。
- 肩高、身体重心和上衣外轮廓可随动作做小幅变化。
- 前臂和块状手掌只在语义需要时从画面边缘进入；不画手指，不建立完整手势库。
- 汗滴、加载点、屏幕边、耳机等道具和符号位于身份层之外。

### 2.3 禁止项

- 不增加任何功能性五官；语义失败时先改动作和停顿，不能用眼嘴补救。
- 不把脸区改成显示器、表情屏或发光状态核心。
- 不圆角化发型和脸区，不加入发丝、外部分离条、完整描边、高光渐变、抗锯齿或柔边。
- `32×32` 母版不画两条领口斜线；原参考中的细直线无法在该网格下无损保留，不能用粗阶梯代替。
- 不改成长腿、全身或完整上半身角色，不加入复杂服装、武器和场景。
- 不套用方芯的缺角、状态核心、无手脚结构或既有动作编号。

## 3. 网格与构图

| 项目 | 当前规则 |
| --- | --- |
| 身份母版原生网格 | `32×32` |
| 动画工作框 | `48×48` |
| 缩放 | 仅整数倍最近邻；评审图不得用平滑插值 |
| 默认身体范围 | 正面半身；中性母版不出现手臂 |
| 动作遮挡 | 手或道具不得遮挡超过约四分之一脸区 |
| 小尺寸检查 | 原尺寸、`50×50` 实际显示模拟、浅色背景、深色背景 |

`32×32` 是身份设计网格，不等于最终平台投稿尺寸。平台导出只能从批准母版和透明工作帧放大或装配，不能把平台尺寸反向当成原生绘制网格。

## 4. 色板

批准母版 v1 使用 5 个身份色和透明色：

| 用途 | RGBA | 规则 |
| --- | --- | --- |
| 透明 | `#00000000` | 画布与角色外部 |
| 头发 / 中缝 | `#121016FF` | 最深身份色，不使用纯黑渐变 |
| 脸区 | `#F6EFCBFF` | 保持完整、无纹理 |
| 颈部阴影 | `#DDD39EFF` | 只承担结构分层 |
| 紫衣主色 | `#82479DFF` | 冷紫身份主色 |
| 紫衣暗面 | `#643579FF` | 仅用于袖侧和结构暗面 |

冷蓝或暖黄效果色可以在表情包阶段另行定义，但不得进入中性身份母版。中性母版不添加浅色外部分离条；深色背景可读性作为审阅项保留，不靠额外装饰边补救。

## 5. 动作语言

- 默认第一帧必须已经是主语义姿态。用户明确指定的过程型动作可以从前态或空白起步，但必须把最终语义设置为最长停留帧，并单独检查静态预览风险。
- 默认节奏是“主语义长停顿 → 极小回弹或抖动 → 回到主语义并闭环”。
- 主要表达通道依次为：身体重心、头部倾角、肩线、前臂、现实工作道具、通用符号。
- 不使用夸张 squash/stretch；单次形变默认限制在 1–2 像素。动作语义确实要求方向改变时，可整体旋转完整身份块，但不能拆散头发与脸区。
- 道具优先使用屏幕边、耳机、加载点、汗滴等通用元素，不用终端、CPU、代码窗口承担主语义。
- 文字默认采用“失败触发”策略：动作修改后仍无法区分时，才允许后期加入短文字。用户明确要求文字承担过程叙事时可作为例外，但必须确定性绘制并单独检查小尺寸可读性。

## 6. 第一轮验证

批准母版后只制作三张动态试片：

| 语义 | 验证目标 | 禁止捷径 |
| --- | --- | --- |
| `收到` | 点头失败后加入的 `GOT / IT!` 气泡能否明确读成角色发言 | 不增加嘴或其他五官 |
| `工作中` | 前臂、身体前倾和键盘能否直接读成持续敲击 | 不加眼睛模拟视线 |
| `崩了` | 能否依靠从母版坐直到横趴键盘的完整身体过程表达崩溃 | 不依赖故障图标或文字 |

当前没有外部盲测条件，由用户直接验收。评审时三张试片随机排列且不显示名称，同时展示原尺寸、`50×50`、浅色背景和深色背景；先判断三张能否互相区分，再对照预设语义。

用户于 2026-07-15 确认三张身份动作试片通过，可以展开首包。后续包评审将两个倒地动作重新分配：[`trials/v3/README.md`](trials/v3/README.md) 的侧趴键盘用于“崩了”；[`trials/v4/README.md`](trials/v4/README.md) 的正面全黑头顶去掉键盘后用于“磕头”。历史试片集仍只用于追溯，当前语义以包动作卡为准。

## 8. 研究结论的取舍

- 采用 [`../research/report.md`](../research/report.md) 的 A 方向：严格无脸、半身、`32×32` 身份网格和 `48×48` 动画工作框。
- 不采用 [`../research/report2.md`](../research/report2.md) 把可开关五官和 `48×48` 母版作为主路的建议。
- 两份报告共同支持的有限色板、Indexed 思路、透明硬边、人工像素定稿、三张试片和“现代工作聊天”定位继续有效。
- 两份报告中未导入仓库的 `sandbox:/mnt/data/...` 概念图不构成批准依据。
