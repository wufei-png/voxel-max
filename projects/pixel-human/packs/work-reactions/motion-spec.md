# `work-reactions` 动作卡

- 状态：`approved_for_production`
- 身份规范：[`../../identity/spec.md`](../../identity/spec.md)
- 动作来源：[`../../identity/trials/v3/README.md`](../../identity/trials/v3/README.md)、[`../../identity/trials/v4/README.md`](../../identity/trials/v4/README.md)
- 原生身份网格：`32×32`
- 动画工作框：`48×48`

## 共通规则

- 默认首帧是可独立阅读的主语义姿态并闭环。用户明确指定的过程型动作可以从前态开始：`S01` 从短消息卡进入输入点与回复，`S05` 从空白绘制对号，`S08` 从坐在座位开始；这三张必须在末段长停最终语义。
- 保持无脸、黑色硬边发块、暖米色脸区、两层紫色肩阶和 4 像素逻辑宽中缝。
- 仅使用整像素位移、最近邻缩放和二值 Alpha；禁止抗锯齿、半透明边缘与渐变。
- 默认 5–7 帧、约 `1.0–1.4s`；主语义停留应明显长于过渡帧。`S08` 使用 12 帧高帧率过程动画，不把这一复杂度扩散到其他动作。
- 文字默认采用失败触发策略。`S01` 的 `GOT / IT!` 已经通过；`S08` 按用户明确设计使用逐字“下班了”；其余动作保持无字。
- 道具不能遮挡超过约四分之一脸区；耳机与麦杆必须使用块状结构，不画孤立细线。

## QA 门槛

1. 不看名称时，九张的主语义停留帧仍可互相区分；`S05 / S08` 另检查起始过程是否符合用户指定。
2. `S02 / S03 / S04` 分别读成正在处理、请求等待和暂不可回复，不能都像“盯电脑”。
3. `S05 / S07` 的成功与失败必须主要靠身体重心相反来区分。
4. `S06` 的三点属于停顿符号，不能看成 `S03` 的加载进度；位置、色彩节奏和身体姿态都应不同。
5. `S07` 必须靠侧脸、键盘和单次瘫倒读成崩溃；`S09` 必须靠无键盘、连续前臂连接块状手掌、正面对称和重复下拜读成磕头，不能依赖装饰冲击线。
6. 所有源帧保持 `48×48` RGBA、二值 Alpha、批准母版色值和整数像素边缘。
